# MANS 네이티브 아키텍처

## 목표

MANS는 임무 계획과 현장 항법에 쓰는 macOS 데스크톱 도구로 전환한다. 첫 단계는 웹 앱을 대체하지 않는다. 공통 Rust 항법 코어를 데스크톱 창에서 직접 실행하고, 지형·경로·검사 정보를 하나의 작업 표면에 배치한다.

## 선택: eframe + egui + wgpu

초기 데스크톱 프런트엔드는 `eframe`과 `egui`를 사용하고 `wgpu` 렌더러를 선택한다. 이 조합은 macOS에서 단일 Rust 실행 파일로 창, 메뉴, 도킹 가능한 패널의 기반을 제공하며, 지형 검증 화면을 빠르게 구현할 수 있다. Bevy는 향후 대규모 3D 장면과 고급 상호작용이 필요할 때 다시 평가한다. 현재 단계에서는 ECS와 게임 런타임이 필요 이상으로 복잡하다.

## 워크스페이스

```text
NasaSpaceAppChal/
├── apps/
│   └── desktop/            # eframe 기반 macOS 앱
├── crates/
│   └── mans-nav/           # 순수 Rust 경로·경사·상태 추정 코어
├── data/                   # 지형 데이터와 변환 스크립트
├── src/                    # 기존 웹 앱, 이동하지 않음
└── docs/
```

루트 Cargo 워크스페이스는 `apps/desktop`과 `crates/mans-nav`를 관리한다. 웹 의존성과 Rust 의존성은 분리한다.

## 데스크톱 작업 표면

초기 화면은 하나의 지형 작업 공간으로 구성한다.

- 상단 메뉴와 도구 모음은 경로 계산, 시작점·목표점 선택, 위험 회피 설정을 제공한다.
- 가운데 뷰포트는 고도와 경사를 구분해 그린 격자, 선택점, 경로를 표시한다.
- 왼쪽 탐색기는 활성 데이터 레이어를 제어한다.
- 오른쪽 검사는 커서 위치의 좌표, 고도, 경사, 경로 요약을 보여 준다.
- 하단 상태 영역은 선택 상태와 고도 프로파일을 보여 준다.

패널은 사용자가 크기를 조절할 수 있다. 정보는 항상 카드로 나열하지 않고, 지도에서 선택한 항목의 문맥으로 표시한다.

## 데이터와 좌표 계약

초기 로더는 JSON의 `size`, `cellSize`, `heights`, `source`, `provenance`와 선택적 `metadata`를 읽는다. 격자 인덱스는 `mans-nav::Point { x, z }`로 변환한다. 기본 데이터는 NASA MGS MOLA `MEGT44N000HB.IMG`에서 18.444°N, 77.450°E를 중심으로 추출한 16 × 16 관측 창이다. 좌표는 IAU2000 planetocentric, east-positive, Simple Cylindrical이며, 고도는 GMM3 areoid에 대한 MOLA topography다.

NASA DTM과 궤도 영상을 추가할 때에는 다운로드 원본, 제품 ID, 좌표계, 해상도, 처리 시각을 별도 메타데이터로 기록한다. 관측 데이터가 없으면 앱은 시뮬레이션 데이터임을 화면에 표시한다.

## 단계별 이행

1. Rust 워크스페이스, 네이티브 창, 샘플 지형, 공통 A* 경로를 연결한다.
2. MOLA 관측 창과 GeoTIFF 변환 결과를 읽고 고도·경사·위험 레이어를 데이터 기반으로 만든다.
3. 계획 작업 공간에 경로 후보 비교, 고도 프로파일, 위험 검사와 저장 가능한 임무 문서를 추가한다.
4. 현장 항법 작업 공간을 별도 모드로 구현해 방위, 다음 웨이포인트, 신뢰도를 중심으로 표시한다.
5. 센서 입력, 좌표 변환, 로그 재생, 데이터 출처 검증을 추가한다.

## 검증 기준

각 단계에서 다음을 확인한다.

- `cargo build -p mans-desktop`이 macOS에서 성공한다.
- `cargo test -p mans-nav`이 경로와 추정 회귀를 검증한다.
- 데스크톱 앱이 샘플 지형을 열고, 클릭한 시작점·목표점 사이의 경로를 다시 계산한다.
- 데이터 출처가 없거나 시뮬레이션일 때 해당 상태가 사용자 인터페이스에 드러난다.
